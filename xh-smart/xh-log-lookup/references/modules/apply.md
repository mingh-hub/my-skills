# 借款申请日志查询

`apply` 模块处理正式下单之前的客户借款申请链路，包括用户登录后进入借款首页、借款内容页、借款试算页、借款能力预检、提交借款申请前后的行为轨迹和失败原因定位。CLS 执行、加载更多、飞书卡片优先输出和纯文本 fallback 统一交给 `xh-log-lookup` 主控工具。

> 当前文件先提供模块基础架构。具体接口、日志锚点、推荐查询和失败场景，后续基于客户借款申请业务流程说明文档和本地代码补齐。

## 模块定位

- **申请前链路**：用户登录、访问借款首页、进入借款内容页、借款试算、借款能力校验、提交借款申请时的页面和接口行为轨迹，默认走 `apply` 模块。
- **正式下单链路**：订单生成、下单请求、下单拦截、反欺诈、订单状态、下单成功/失败统计，继续走 `references/modules/order.md`。
- **放款链路**：资金路由、放款等，继续走 `references/modules/loan.md`。

## 涉及服务

主服务：`h5-loan`。

常见关联服务：`order`、`cif`、`account`、`datainquiry`、`weixin-h5api`、`app-server`。

> 关联服务只作为后续链路钻取范围；首查应优先从 `h5-loan` 的申请前入口日志定位 `cid/traceId/mobileNo/identityNo` 等桥接标识。

## 意图边界

- **行为轨迹查询**：用户问"客户从登录到申请借款的轨迹"、"借款首页有没有进来"、"试算页卡在哪"、"客户申请前做了什么"、"借款失败"时，按 `apply` 查询。
- **申请前失败原因**：用户问"借款内容页失败"、"借款试算失败"、"借款能力校验不通过"、"首页不展示借款入口"、"首页不展示借款额度"时，按 `apply` 查询。
- **提交后正式下单**：用户明确问"下单失败"、"订单为什么没生成"、"反欺诈拦截"、"下单成功/失败统计"时，按 `order.md` 查询；`apply` 只负责定位提交前后是否已进入下单链路。
- **签约/绑卡/还款/权益**：客户申请过程中如果跳转到签约、绑卡、权益勾选或还款补充链路，应按对应模块继续钻取，`apply` 只保留前置轨迹证据。

## 首查策略

手机号、身份证号等自然标识只能作为定位入口。查到 `cid/traceId` 后，必须继续用稳定标识符追踪申请前链路；`orderId` 只作为已进入正式下单后的桥接标识，不作为 apply 首查主入口。

| 用户提供 | 推荐首查语句 | 说明 |
|----------|--------------|------|
| `traceId` | `traceId:"{value}"` | 全链路直查，不加 `serviceName` |
| `cid`、`userId`、`customerId` | `serviceName:"h5-loan" AND message:"{value}"` | 当前为占位首查，后续补稳定日志锚点 |
| 手机号 | 先定位 `cid`，再按 `cid` 查 apply 链路 | 具体定位入口待补充 |
| 身份证号 | 先定位 `cid`，再按 `cid` 查 apply 链路 | 身份证可能脱敏，不能只凭无结果下结论 |

## 核心流程链路追踪模板

| 场景 | 方法入口 | 日志锚点/关键词 | 推荐查询 | 关键指标 | 说明 |
|------|----------|----------------|----------|----------|------|
| 借款首页 | 待补充 | 待补充 | 待补充 | 首页卡片、借款入口、可借状态 | 判断客户是否进入借款首页及首页展示结果 |
| 借款能力校验 | 待补充 | 待补充 | 待补充 | 是否可借、拦截原因、风控/逾期/额度状态 | 判断申请前能力校验是否通过 |
| 借款内容页 | 待补充 | 待补充 | 待补充 | 金额、期数、渠道、定价、优惠券、权益 | 判断试算页内容是否正常返回 |
| 借款试算 | 待补充 | 待补充 | 待补充 | 还款计划、费率、期供、试算结果 | 判断试算接口是否成功及失败原因 |
| 提交借款申请 | 待补充 | 待补充 | 待补充 | 提交参数、申请结果、桥接 `cid/traceId` | 成功进入正式下单后继续参考 `order.md` |

## 关键失败场景

| 现象 | 优先诊断 |
|------|----------|
| 登录后无法进入借款首页 | 待补充：确认登录态、客户身份、首页入口接口返回 |
| 借款首页无入口或卡片异常 | 待补充：确认首页卡片、客户可借状态和展示规则 |
| 借款能力校验/预检不通过 | 待补充：确认能力校验接口、拦截原因和上下游服务返回 |
| 借款内容页失败 | 待补充：确认内容页接口、额度/期数/定价/优惠券/权益等返回 |
| 借款试算失败 | 待补充：确认试算请求、还款计划、费率和资方/定价返回 |
| 提交申请后未进入下单 | 待补充：确认提交接口结果，并用桥接标识联动 `order.md` |

## 健康检查

apply 健康检查属于统计模式，必须遵守主控的完整性和采样输出规则。当前只保留分区框架，具体 SQL 待锚点补齐后再启用。

| 场景 | 查询 SQL | 说明 |
|------|----------|------|
| 申请前链路 ERROR | 待补充 | 只统计 apply 链路相关错误 |
| 申请前链路 WARN | 待补充 | 只统计 apply 链路相关告警 |
| 借款内容/试算异常 | 待补充 | 后续按稳定锚点拆分 |
| 提交申请入口量/结果量 | 待补充 | 仅用于申请前到正式下单的桥接观察 |

## 输出要求

结论必须说明：

- 用户问题属于登录/首页、借款能力校验/预检、借款内容页、借款试算、提交申请，还是已经进入正式下单。
- 查到的标识符：`cid/traceId`，以及手机号、身份证号是否只是定位入口；如果已经进入正式下单，再说明桥接 `orderId`。
- 按时间顺序输出客户行为轨迹：登录 -> 首页 -> 预检 -> 内容页 -> 试算 -> 提交申请 -> 正式下单桥接。
- 明确每个节点是否命中日志、返回是否成功、失败原因是否来自本服务还是下游服务。
- 如果已经进入正式下单，必须说明后续应按 `references/modules/order.md` 的下单链路继续排查。
