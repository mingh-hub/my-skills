# 质量检测模式（qa）

像互联网产品测试一样，对小说进行系统性质量检测。核心价值：**发现问题、分级记录、追踪闭环**。**只读其他设定/正文文件，绝不修改**（见 SKILL.md 只读边界）。

## 1. 触发条件

- **首次检查**：「检查一下第 X 章」「帮我测试这篇小说」「QA 一下」「检查 ke-novel-continuation 卷二第 5 章」
- **回归测试**：「回归测试」「复核上次的问题」「回归一下」
- **问题管理**：「这个不是问题」「QA-003 忽略」「关闭 QA-005」

## 2. 检查维度（10 大维度概览）

逐维度审查，详细定义与示例见 `references/modules/qa/check-dimensions.md`：

| 维度 | 一句话说明 |
|------|-----------|
| 1 人设一致性 | 性格、口头禅、行为习惯、年龄、外貌是否前后矛盾 |
| 2 时间线一致性 | 日期/时间顺序、事件先后、年龄与时间对应，籍贯与"来/去某城市"表述是否自洽 |
| 3 情节逻辑 | 因果、动机、行为逻辑；含生活常识与**空间逻辑自洽**；同一关键事件多章版本是否一致 |
| 4 对话合理性 | 说话方式合人设、引用过往准确、前后呼应、避免"忽然知情"式突兀、语境社交语感是否违和 |
| 5 伏笔闭环 | 已埋伏笔是否回收，有无悬而未决线索 |
| 6 称呼/称谓一致性 | 角色互称、叙述者称呼、昵称是否前后统一 |
| 7 场景/环境一致性 | 地点/布局/天气/时间段是否矛盾；**对项目须对照 `novels/[proj]/spaces.md`** 核对同一空间描写 |
| 8 物品/道具一致性 | 关键物品的出现、转移、消失是否合理 |
| 9 情感逻辑 | 角色情绪反应是否符合性格与情境 |
| 10 世界观/设定一致性 | 小说内在规则是否自洽（游戏机制、时代背景、超自然设定） |
| （附）文风自然度 | 是否存在明显 AI 味写法（机械罗列、模板句、跨章自我复制、破折号过密、词汇过度使用、结构化排比、场景切入单一）。检出细则对照 `references/common/anti-ai-style.md`（审阅侧 5-6 次阈值） |

## 3. 问题等级定义

| 等级 | 标签 | 含义 | 示例 |
|------|------|------|------|
| 致命 | BLOCKER | 完全破坏故事逻辑，读者无法继续 | 已死角色无故出现；主线剧情自相矛盾 |
| 严重 | CRITICAL | 认真读者必然发现的重大不一致 | 人设崩塌；关键时间线错乱 |
| 一般 | MAJOR | 可感知但不破坏阅读的问题 | 次要角色细节前后不一；情感反应略显突兀 |
| 轻微 | MINOR | 瑕疵级别，不影响阅读体验 | 称呼偶尔不统一；环境描写小矛盾 |

## 4. 首次检查流程

1. **确定检查范围**：用户指定章节文件路径或直接粘贴文本。
2. **加载参考设定**（项目模式）：
   - `novel-creator` 项目：读取对应小说项目的 `novels/[proj]/` 下 `meta.md`、`characters.md`、`timeline.md`、`outline.md`、**`spaces.md`（空间布置；若不存在则用 `setting-layout.md`）**。
   - `ke-novel-continuation` 等**外部项目**：读取用户提供路径下的 `characters.md`、`timeline.md`、`outline.md`（本技能不内置其文件）。
   - 独立文本：跳过此步，仅基于文本内部逻辑检查。
3. **逐维度检查**：按 10 大维度逐一审查，记录问题。
4. **输出缺陷清单**：按等级从高到低排列（BLOCKER → CRITICAL → MAJOR → MINOR）。
5. **保存报告**：写入技能根 `reports/[项目名]-[日期].md`（模板见 `references/common/output-report-templates.md` 输出 5）。

## 5. 回归测试流程

1. 读取最近一次 QA 报告（`reports/` 下对应项目）。
2. 对状态为 OPEN 的问题逐一复核：已修复→`FIXED`；未修复→保持 `OPEN`；用户明确说不是问题→`WONT_FIX`（仅用户明确声明后）。
3. 检查修复过程中是否引入新问题。
4. 更新报告文件。

## 6. 问题追踪规则

- 每个问题有唯一编号（如 `QA-001`）。
- 状态流转：`OPEN` → `FIXED` / `WONT_FIX`。
- **除非用户明确说「这个不是问题」或「忽略」，否则每次回归都必须继续反馈 OPEN 状态的问题。**
- `WONT_FIX` 的问题后续不再反馈。

## 7. 报告输出与存放

- 报告模板见 `references/common/output-report-templates.md` 输出 5。
- 所有 QA 报告存放技能根 `reports/`，命名 `[项目名]-[YYYYMMDD].md`（如 `ganxiang-20260209.md`、`standalone-20260209.md`）。`reports/` 下的示例报告见该目录 README 标注。

## 8. 与其他模式的协作

- 本模式只读取设定/正文文件（`characters.md` 等），**不修改**它们。发现问题后由用户决定是否切到「章节写作」模式修改。
