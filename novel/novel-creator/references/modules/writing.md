# 章节写作模式（writing）

本模式是通用小说创作与管理引擎，支持同时管理多部不同类型的小说：创建项目、续写章节、维护大纲与设定、通过学习样本进化写作风格。写章节时**必须执行强制六步流程，不可跳过**。

> **写作铁律**见 SKILL.md `## 强制规则 > 写作铁律`（六条，违反任一视为写作失败）。本文件是六条铁律的落地流程。

## 1. 核心功能与触发

### 1.1 项目管理
- **创建新小说**：触发「创建新小说」「新建小说项目 [项目名]」「根据 init.md 创建项目」。在 `novels/` 下创建新文件夹，生成基础设定文件（meta, outline, timeline, characters, spaces）。

### 1.2 章节写作
- **续写/写作**：触发「写 [项目名] 的第 X 章」「续写 [项目名]」「为 [项目名] 写一章」。按 §3.2 **强制六步流程**执行，六步不可跳过。

### 1.3 设定维护
- **更新设定**：触发「更新 [项目名] 的设定」「同步 [项目名] 的大纲」「读取 [项目名] 的 updates.md」。读取用户修改的 `updates.md`，智能更新 `outline.md`、`timeline.md`、`characters.md` 和（若有空间相关内容）`spaces.md`。
- **回归大纲（反向同步）**：触发「按照文章回归一下大纲」「将正文同步回大纲」「根据章节内容更新设定」。读取已写章节，提取关键情节/时间点/人物，反向更新设定文件，确保设定与正文一致。

### 1.4 自我进化
- **学习进化**：触发「学习新样本」「我放了新范文在 samples 里」「帮我按新范文更新风格」。分析样本，提炼技巧，更新去 AI 化规则库与本 module 的风格描述（见 §5）。

## 2. 目录结构

所有小说存放在技能根 `novels/` 目录下，每个项目独立一个文件夹；完整 schema 与各文件模板见 `references/common/data-contracts.md` §1 与 `references/common/file-templates.md`。

## 3. 工作流

### 3.1 创建新小说

1. **获取信息**：确认小说名、类型、项目代号（文件夹名，如 `my-novel`）、故事概况、核心主题、最终走向。若用户提供了 `init.md`（可选种子文件，模板见 `references/common/file-templates.md`）则据此读取；未提供则引导用户提供，或直接在对话中收集这些信息。
2. **创建目录**：建立 `novels/[project-name]/` 及子目录 `chapters/`。
3. **生成文件**（模板见 `references/common/file-templates.md`）：`meta.md`、`outline.md`、`timeline.md`、`characters.md`、`spaces.md`（**空间布置**，与大纲同时生成，预设重要空间避免前后描写不一）、`updates.md`（空文件）。
4. **反馈**：告知用户项目已创建。

### 3.2 章节写作（强制六步流程）

> **铁律**：以下六步**必须按顺序执行，不可跳过任何一步**。跳过任何一步直接写作，所写内容无效，必须推翻重来。

#### Step 1: 强制加载上下文（不可跳过）

先定位项目（若未指定且只有一个项目，默认该项目；否则询问），然后**必须逐项读取以下文件，全部读完才能动笔**：

1. **本 module（writing.md）与 SKILL.md 强制规则**（确认写作规则）
2. **meta.md**（类型、风格、主题）
3. **outline.md**（至少读必须遵守内容和当前章节 + 前后各一章的大纲）
4. **timeline.md**（对照当前章节的时间节点）
5. **characters.md**（本章涉及的人物设定、性格、关系）
6. **spaces.md**（本章涉及的空间布局与陈设）
7. **`references/common/anti-ai-style.md`**（去 AI 化写作规范）
8. **上一章全文**（`chapter_N-1.md`，必须完整读取）
9. **前 2-3 章**（`chapter_N-2`、`N-3`、`N-4`，至少各读开头、结尾和关键段落）
10. **风格参考文件**（若 meta 指定引用风格 → 读取 `styles/[作品名].md`；若 meta 或用户当次指定「mingh 风格」→ 读取 `references/modules/mingh-style-writer.md` 的声线规范）

**如果已在同一对话中读取过以上文件且内容未变，可不重复读取，但必须在回复中明确说明"已在本次对话中读取过 XXX"。首次写作必须全部读取，没有例外。**

#### Step 2: 风格进化分析（不可跳过）

动笔之前，**必须先输出一段风格分析给用户看**，不能默默跳过：

1. **精读上一章（N-1）**：提取句式节奏、情感密度、描写手法、对话风格、环境描写比重等具体特征。
2. **对比前 3 章（N-2 ~ N-4）**：找出上一章相比之前的进步和亮点——哪些写得更好了？哪些手法值得继续用？
3. **总结继承清单**：明确列出本章应继承和发扬的风格特征（至少 3 条具体特征）。

**风格优先级（从高到低，严格执行）**：
- **最高**：用户当次指定的风格（如「按 XXX 风格写」「这章轻松一点」）
- **第二**：上一章的实际写作风格（最新标杆，已含用户修改后的版本）
- **第三**：前 3 章的风格趋势（整体基调参考）
- **第四**：meta.md 中的项目风格设定（初始定义）
- **兜底**：`references/common/anti-ai-style.md` + 本 module §4 通用风格

**核心原则：已写的章节（尤其用户改过的）才是最准确的风格参考。meta.md 只是初始设定，不能覆盖已经进化过的实际风格。写作只能越来越好，不能退步。**

#### Step 3: 对话反馈规避（同一对话内生效）
- **同一对话中修改过前面章节或用户表达过不满**：回顾本次对话所有修改要求和不满，提炼"规避清单"展示给用户（如：不要纯对话流、不要跳过环境描写、不要用"他不知道..."收尾），写作时**严格规避**。
- **新对话**：跳过此步。

#### Step 4: 大纲要点提取（不可跳过）

从 outline.md 提取当前章节的**所有关键要点**，生成编号清单展示给用户：

```
本章大纲要点清单：
1. 刘浪到工厂报到，第一次见到车间环境
2. 与室友阿瓜在宿舍的初次互动
3. 夜班第一晚——流水线的机械感和疲惫感
...
```

**大纲里写的每一个要点，正文必须全部覆盖，一个都不能少。** 遗漏大纲要点等于无视用户需求。若 outline 开头有「必须遵守」区块（如单章字数、对话呈现等），其条款须一并纳入要点清单，Step 6 逐条对照。

#### Step 5: 执行写作

按以上准备动笔，**必须同时满足**：
1. **风格**：严格遵循 Step 2 结果，以上一章实际风格为标杆，只能更好不能退步。
2. **内容**：严格覆盖 Step 4 所有大纲要点，一个不漏。
3. **规避**：严格执行 Step 3 规避清单（如有）。
4. **规范**：遵守 §4 通用风格 + `references/common/anti-ai-style.md`（去 AI 化、禁对话流、章节承接等）。
5. **空间**：本章涉及空间严格参照 `spaces.md`，不得与预设矛盾。
6. **合理性**：若用户要求与大纲/时间线冲突，**必须暂停询问用户**，不能自行发挥或编造。
7. **输出**：Markdown 格式正文。

#### Step 6: 大纲覆盖检查与文风/表达重复自查（不可跳过）

写完后**必须完成两项检查，缺一不可**：

**6.1 大纲覆盖检查**——逐条对照 Step 4 清单，输出检查结果：

```
大纲覆盖检查：
1. 刘浪到工厂报到 → ✅ 已覆盖
2. 与室友阿瓜互动 → ✅ 已覆盖
3. 夜班第一晚 → ❌ 未覆盖
...
```
- 有未覆盖要点**必须立即补写**，补完重新检查，直到全覆盖。**未全覆盖视为未完成，不能提交。**

**6.2 文风与表达重复检查（硬性步骤）**——保存前**必须**：
1. **统计前文同类表达**：用 grep/搜索在 `chapters/` 下已写章节中检索 `references/common/anti-ai-style.md`「全文禁用/慎用表达清单」的典型词汇（如：指节发白、手心出汗、心跳漏了一拍、愣了一下 等）。
2. **对照清单检查本章**：若某表达在前文已出现 **2 次及以上**，本章正文**不得再使用**，必须替换。
3. **结构化对比句式检查**：检查本章是否出现「不是...是...」「不是...而是...」等结构化对比句式；若有**必须**改写为自然表述。
4. **输出检查结果**给用户看：

```
表达重复检查：
- 指节发白/泛白：前文已出现 X 次（ch.Y, ch.Z…）→ 本章已避免/已替换
- 手心出汗：前文已出现 X 次 → 本章已避免/已替换
- 结构化对比句式（不是...是.../不是...而是...）：本章已避免/已替换
- 本章无新增重复 ✅
```
- **若本章使用了前文已超 2 次的表达，视为文风违规，必须修改后再保存。**
- 全部检查通过后，保存到 `novels/[project-name]/chapters/`。
- **可选 QA 衔接**：写完后可建议切到本技能「质量检测」模式对人设、时间线、空间布置、对话呼应等做一致性检查。

### 3.3 设定更新

当用户修改 `updates.md` 并要求更新/同步时，按 `references/common/data-contracts.md` §2 的读取与归档契约执行：只以 `## 待更新内容` 为准 → 分析新剧情/人物/空间 → 检测与已写章节冲突（冲突则警告并给方案）→ 整合进 `outline/timeline/characters`（有空间则同步 `spaces.md`）→ 归档（改名 + 保留原稿 + 追加空段）。

### 3.4 回归大纲（反向同步）

当用户要求"按照文章回归一下大纲"时：
1. **读取正文**：读取指定范围（如"前5章""全部章节"）。
2. **提取信息**：情节（关键事件/场景/对话）、时间线（时间标记）、人物（出现人物/关系/行为）、空间（已出现场所的布局/陈设/方位）。
3. **对比现有**：与当前 `outline.md`、`timeline.md`、`characters.md`、`spaces.md` 对比。
4. **更新设定**：补充大纲缺失细节、完善时间线节点、补充人物关键场景锚点、将稳定出现的空间补进 `spaces.md` 或修正矛盾预设。
5. **反馈**：告知已同步内容，冲突或不确定处需用户确认。

**适用场景**：边写边改正文已偏离大纲；整理已写内容确保设定与正文一致；长期/多人项目需同步最新进展。

### 3.5 章节大纲规划规范

大纲的目的、轻量模板、编写原则与丰满化规范见 `references/common/file-templates.md`（outline.md 节）。**大纲中出现的所有内容，无论格式，写作时必须全部覆盖——这是铁律。**

## 4. 写作风格规范

本节定义通用写作风格（§4.1）与类型适配（§4.2），作为**兜底规范**。**去 AI 化细则（禁忌表达、检查方法、双档阈值）见 `references/common/anti-ai-style.md`**，写作前必须读取。实际写作时风格优先级见 §3.2 Step 2——**已写章节的实际风格优先于 meta 设定和本节默认规范**。`meta.md` 的 **写作风格** 字段（通用 / mingh / 引用《作品名》）作为初始设定；随章节推进风格应持续进化，不回归初始设定。mingh 风格为在通用风格基础上的「mingh 融合版」，兼顾小说叙事的沉浸感与个人随笔的真诚感（声线见 `references/modules/mingh-style-writer.md`）。

### 4.1 通用风格（Base Style）

- **人称**：第三人称（POV）。视点人物用"他/她"，但心理描写深入，达到"虽是第三人称，却有第一人称的代入感"。
- **口语化**：叙述语言自然流畅，不拿腔拿调。允许适度使用角色口头禅或方言词汇（视人设而定）。
- **去对话化**：**严禁纯对话推进剧情**。每段对话之间必须穿插动作、神态、心理活动或环境描写。
- **避免流水账**：**严禁只罗列事件**。每个场景都要有沉浸感——具体空间、光影、声音、气味，人物动作、神态、心理，以及场景之间的情绪流动。正确做法是"慢下来"，让读者进入场景。
- **对话语气词**：**对话必须包含语气词**，表达说话人的情绪。不说"我不知道"，而说"哎呀，这我哪儿知道啊"；不说"你怎么来了"，而说"咦，你怎么来了？"。常用：啊、呢、吧、嘛、呀、哦、嗯、唉、哎、哟、哈、哇、哼、呃等，按人物性格和情境灵活运用。
- **群像对话有互动**：多人场景中配角之间也要有互动，可互相调侃、打嘴炮、抬杠，制造张力，别都围着主角转。
- **情感颗粒度**：捕捉细腻的情绪变化，不只写"他生气了"，要写"他捏着茶杯的手指关节泛白"。
- **冲突与回报**：大胆设置困境与误会，不急于解决；压抑之后必须给予明确的情绪释放（爽感/治愈/释然）。
- **文风去 AI 化**：避免 AI 味表达（破折号滥用、同一意思反复、特定词汇过度、三连排比、刻意对称、议论文式过渡词、翻译腔/公文腔、结构化对比句式"不是...而是..."）。**详见 `references/common/anti-ai-style.md`。**
- **章节内词汇多样化**：**一章内禁止重复使用相同的修饰词、动作描写或心理表达**。如"心跳漏了一拍""愣了一下"等，一章内只能用一次，第二次必须换说法。
- **减少正确废话与没落点**：少写 综合来看、从某种意义上、或许、可能 等模板句或模糊兜圈句。情绪或选择要有具体依据；章节或场景收尾要有具体落点（情绪/画面/行动落点），不泛泛升华。
- **不装腔**：不堆砌大词、不借角色或叙述者之口装深刻。道理用故事和细节展示（Show, Don't Tell）。
- **章节承接**：**新章节开头必须承接上一章的情绪状态**，写出情绪的转变过程，而非硬生生切换场景。
- **结构多样化**：拒绝固定套路——收尾方式多样（留白/定格画面/动作收束/对话掐断），叙述节奏与笔墨分配随章节变化。

### 4.2 类型适配（Genre Adaptation）

根据 `meta.md` 的 `type` 字段调整，要点见 `references/modules/writing/genre-style-details.md`（现代/都市、古代/历史、言情/校园、武侠、科幻、刑侦/悬疑的风格微调）。

## 5. 自我进化机制

当 `samples/`（用户放置的优秀文本样本，`.txt`/`.md`）下增加新文件时，用户触发进化：
1. **读取样本**：读取所有文本。
2. **风格提取**：分析句式长短、修辞习惯、叙事节奏、词汇偏好。
3. **更新规范**：将提取的新特征追加/合并到 `references/common/anti-ai-style.md`（如新增慎用表达）与本 module 的风格描述。
4. **更新描述**：更新本文件 §4 的风格描述部分。

> 样本目录 `samples/` 由用户按需在项目或技能根创建并放置素材；本技能不内置样本。
