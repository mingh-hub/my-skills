# 文件模板与大纲规范

本文件收录小说项目各设定文件的模板，以及大纲编写/丰满化规范。新建项目、设定维护、大纲规划时引用。

## meta.md

```markdown
# 小说元信息

- **项目名**：[folder-name]
- **小说名**：《[Title]》
- **类型**：[Genre]
- **POV**：第三人称
- **写作风格**：通用（可选：通用 / mingh / 引用《作品名》如《伊豆的舞女》；不填则默认通用）
- **状态**：连载中
- **概况**：[Summary]
- **核心主题**：[Theme]
- **最终走向**：[Ending]
```

> **写作风格字段说明**：`通用` = 本技能通用小说风格；`引用《作品名》` = 加载 `styles/[作品名].md` 注入叙事风格（见 `references/modules/style-reference.md`）；`mingh` = 在通用风格基础上融入 mingh 个人叙事声线（兼顾小说沉浸感与个人随笔的真诚感），声线要点见 `references/modules/mingh-style-writer.md`，本技能不再依赖任何外部随笔技能。

## outline.md（大纲）

大纲的目的是**给用户和 AI 一个共同的写作蓝图**，应轻量、易编辑，用户可随时手改。**大纲中出现的所有内容，无论格式，写作时必须全部覆盖——这是铁律。**

### 大纲模板（轻量版）

每一章按以下格式书写（用户也可用自己习惯的任何格式，不限于此模板）：

```
#### 第X章《章节名》

**写什么**：
本章的关键场景、核心事件、重要转折。写清要点即可，不需要事无巨细。

**重点突出**：
本章要着力表现的主题/情感/人物特征。如"刘浪的逃避心理""兄弟关系裂缝初现"。

**备注**：
用户自由补充区。情绪基调、章尾钩子、写法提示、任何想法都可以写在这里。可留空。
```

> 用户可以在大纲中用任何格式补充内容（直接写一段话、列要点、贴对话片段、写情绪关键词），不限于以上三个字段。**写在大纲里的每一句话，AI 写作时都必须覆盖到。**

### 整体叙事逻辑

在章节列表之前，简要说明整幕/整卷的叙事脉络：时间跨度、主要事件链、情绪弧线走向，让人一眼看清这批章节的全貌。

### 编写原则

1. **不是事件清单**：每章的"写什么"不能只写"A 发生了→B 发生了→C 发生了"，要有**场景感**——读者看大纲就能想象到画面。
2. **情绪弧线可见**：多章读下来，情绪应有明显起伏弧线，在大纲层面就能看出设计。
3. **怎么写由风格进化决定**：具体写法（节奏、侧重、视角、技法）不写在大纲里，由 `writing.md` Step 2 风格进化分析动态决定。

### 丰满化规范（AI 生成大纲时必须遵守）

当用户在 `updates.md` 或对话中提供每章要点、AI 将其总结为 `outline.md` 时，**必须遵循**：

1. **只多不少**：大纲的"写什么"必须比用户原始要点**更丰满、更具体、更有场景感**，绝不缩水或概括。用户写两句话，要主动补全空间/画面、人物反应、心理变化。
2. **串故事线**：每章不能只写本章事件，必须交代与前一章的衔接、为后续章节埋的伏笔。
3. **场景化而非概念化**：不能只写"林晓被霸凌"，要写出**具体方式**（藏东西、课桌写字、走廊堵人）；不能只写"刘浪开始冷淡"，要写出**行为变化**（秒回变慢回、甜话变敷衍的"嗯""哦""随便"）。
4. **人物心理必须具体**：不能只说"她很伤心""他不在乎"，要写出伤心的具体表现（手指攥着衣角、声音小到几乎听不见）和不在乎的具体行为（回一个"嗯"然后切回另一个聊天框）。
5. **严格对应用户拆章**：用户自己拆了章节（如 12 条对应 12 章），大纲**严格一一对应**，不自行合并、拆分或重排。

## timeline.md / characters.md

新建时初始化为空框架，随「设定维护」与「回归大纲」逐步补全：
- `timeline.md`：里程碑事件、时间锚点、角色年龄与时间对应。
- `characters.md`：人物小传（目标/缺陷/性格/口头禅/关系/关键场景锚点）。

## spaces.md（空间布置）

根据大纲与故事概况，为**常出现的空间**预设统一布局，写作与 QA 时引用，避免同一房间/学校/村庄/公司等在不同章节描写不一致。

```markdown
# 空间布置

> 常出现场景的布局与陈设预设。在该空间发生的故事须按此描写；若正文修改导致布局变动，请同步更新本文。

## [空间名称 1]（如：学校、男主住处、公司办公室）

- **位置/方位**：……
- **格局**：房间划分、出入口、与其它空间的关系
- **陈设/标志物**：家具、摆设、门窗、光线来源等
- **用途**：谁在此做什么（上课、住宿、办公等）

## [空间名称 2]
（同上，按需列举）
```

## init.md（可选：项目初始信息种子）

用户在「创建新小说」时**可选**提供的一次性种子文件，集中写下建项目所需的初始信息；技能读取它来生成 `meta/outline/timeline/characters/spaces`。它是**输入**（定位类似 `updates.md`），不是长期维护文件，生成完成后可保留备查或删除。用户未提供时，可在对话中直接收集同样的信息。

```markdown
# 项目初始信息（init）

- **小说名**：《[Title]》
- **项目代号**：[folder-name]
- **类型**：[Genre]
- **故事概况**：[Summary]
- **核心主题**：[Theme]
- **最终走向**：[Ending]
- **主要人物**（可选）：姓名 / 目标 / 缺陷 / 关系
- **初始大纲要点**（可选）：分幕或分章要点，供生成 outline.md
- **重要空间**（可选）：常出现场景，供生成 spaces.md
```
