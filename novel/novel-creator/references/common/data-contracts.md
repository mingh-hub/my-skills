# 数据契约与目录约定

本文件定义 novel-creator 各模式共享的目录结构、交接段落与归档规则。调研规划、章节写作、设定维护、质量检测都依赖这里的契约。

## 1. `novels/` 目录 schema

所有小说存放在技能根 `novels/` 目录下，每个项目独立一个文件夹：

```
novels/
└── [project-name]/
    ├── meta.md             # 元信息（书名、类型、主题、POV、写作风格等）
    ├── outline.md          # 结构化大纲
    ├── timeline.md         # 时间线
    ├── characters.md       # 人物小传
    ├── spaces.md           # 空间布置（常出现场景的布局预设，避免前后描写矛盾）
    ├── updates.md          # 用户输入的新设定/草稿（用于更新上述文件）
    └── chapters/           # 章节正文目录
        ├── chapter_01.md
        └── ...
```

各文件模板见 `references/common/file-templates.md`。

> **可选种子文件 `init.md`**：用户在「创建新小说」时**可选**提供，集中写下建项目所需的初始信息（书名/项目代号/类型/概况/主题/走向，及可选的人物、大纲要点、空间）。技能据此生成上述维护文件。它是**一次性输入**（定位类似 `updates.md`），非长期维护文件，生成后可保留备查或删除；模板见 `references/common/file-templates.md`。

## 2. `updates.md` 交接契约（`## 待更新内容`）

`updates.md` 的 `## 待更新内容` 段落是**调研规划 → 设定维护**的交接口，也是用户手动录入新设定的入口。

**读取规则（设定维护）**：
- 每次更新设定**只以 `## 待更新内容` 段为准**；若该段不存在，视为本次无新增设定，不同步。
- 分析该段中的新剧情、新人物、新空间或空间变更，并检测是否与已写章节（`chapters/`）冲突；冲突则先警告用户并给方案（改旧章 / 仅用于未来），不擅自覆盖。

**归档规则（同步完成后）**：
1. 将 `## 待更新内容` 改名为 `## 已更新内容（更新时间：YYYY-MM-DD）`。
2. **保留用户原稿全文**：先写 `**原稿（保留）**` 小标题列出用户原文，再追加 `**同步摘要**` 说明本次同步到了 outline/characters/timeline/spaces 的哪些位置。**不得只写摘要而删除原稿**，以便回溯对照。
3. 在文件尾部追加一个新的空 `## 待更新内容` 段落，作为下一次更新入口。

## 3. `spaces.md` 空间契约

- `spaces.md` 是**空间布置的唯一真源**：常出现场景（房间、学校、村庄、公司等）的方位、格局、陈设预设。
- **写作**：本章涉及的空间必须严格参照 `spaces.md`，不得与预设矛盾；正文导致布局变动时同步更新本文。
- **质量检测**：维度 7「场景/环境一致性」须对照 `novels/[proj]/spaces.md` 核对同一空间在不同章节的描写是否一致。
- **legacy 别名**：历史项目若无 `spaces.md` 而有 `setting-layout.md`，以 `setting-layout.md` 作为等价回退；新项目一律用 `spaces.md`。

## 4. 调研规划 → 写作 的交接步骤

调研规划模式的产物不直接写入项目文件，需用户确认后迁移：

**开题输出 → outline / timeline / characters**
- **已有项目**：把「调研报告 + 总体故事线」粘贴到该项目 `updates.md` 的 `## 待更新内容`，再用本技能「设定维护」（触发「更新 [项目名] 的设定」）同步到 `outline.md`、`timeline.md`、`characters.md`。内容多时可分批（先大纲+时间线，同步后再粘人物草图）。
- **新项目**：先用本技能「新建小说项目 [项目名]」（信息可从开题报告的「创作目标与主题陈述」提取），再把分幕大纲/时间线草图/人物草图粘到 `## 待更新内容` 后「设定维护」。

**续写输出 → 后续写作**
- 将「未来 3-5 章推进要点」复制到 `updates.md` 的 `## 待更新内容`（可选），或直接保留在对话/报告中；写具体章节时走「章节写作」并参照续写策略报告的推荐路线与节奏建议。

**改写输出 → 执行改写与回归**
- 改写策略报告的「改写蓝图」与「验收清单」供执行时对照；在本技能中「写 [项目名] 的第 X 章」并说明"按改写方案重写"。
- 改写后若与现有大纲不一致，用「回归大纲」（触发「按照文章回归一下大纲」）让正文反向更新 outline/timeline/characters。
- **可选**：改写落地后建议切到本技能「质量检测」模式对人设、时间线、空间布置、伏笔做一致性检查。

## 5. 内部路径速查

| 用途 | 路径 |
|------|------|
| 小说项目根 | `novels/[project-name]/` |
| 需粘贴的交接文件 | `novels/[project-name]/updates.md`（段落 `## 待更新内容`） |
| 被同步的设定文件 | `outline.md`、`timeline.md`、`characters.md`、`spaces.md` |
| 章节正文 | `novels/[project-name]/chapters/chapter_XX.md` |
| 风格摘要库 | `styles/[作品名].md` |
| QA / 调研报告 | `reports/[项目名]-[YYYYMMDD].md` |

> **外部项目**：质量检测也支持 `ke-novel-continuation` 等技能外项目，其 `characters.md`/`timeline.md`/`outline.md` 路径由用户提供，本技能不内置其文件。
